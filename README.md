## اصل معماری
AK1 یک اپلیکیشن مخصوص **مربی** است و هر مربی فقط به **حلقه خودش** دسترسی دارد.
نام حلقه (مثلاً «ابوتراب ۳») نباید در آیکون‌های منوی دسته‌ها یا ساختار عمومی رابط کاربری hard-code شود؛ نام حلقه باید از اطلاعات حساب/حلقه خوانده شود.

ساختار مفهومی:
```
مربی
└── حلقه خودش
    ├── اعضا
    ├── امتیازها
    ├── جلسات
    ├── تراشکاری
    └── رتبه‌بندی اعضا
```

## ورود و هویت حلقه

### حالت آنلاین
هنگام ثبت‌نام مربی:
- نام حلقه را خودش تعیین می‌کند.
- نام کاربری حلقه را خودش تعیین می‌کند.
- رمز عبور تعیین می‌کند.
- در آینده ورود به حساب با نام کاربری حلقه + نام حلقه + رمز عبور انجام می‌شود.
- داده‌ها باید فقط در محدوده همان حلقه قابل دسترسی باشند.

### حالت آفلاین
- برای استفاده محلی نیازی به تعیین رمز عبور نیست.
- اطلاعات روی دستگاه نگهداری می‌شود.
- در تنظیمات امکان **خروجی گرفتن از اطلاعات** وجود دارد.
- خروجی باید شامل داده‌های لازم برای بازگردانی کامل وضعیت حلقه باشد.
- در دستگاه/نصب دیگر، مربی می‌تواند فایل خروجی را از تنظیمات وارد کند و اطلاعات حلقه را **بازگردانی** کند.
- فرمت خروجی باید نسخه‌دار باشد تا در آینده امکان مهاجرت داده‌ها حفظ شود.

## دسته‌های اصلی برنامه
دسته‌ها مستقل از نام حلقه هستند:
